# Salam! — мобильное приложение (Flutter, Android и iOS)

Нативное приложение для иностранных граждан в России: **Документы** (каталог и «Мой список»), **Где оформить**, **Полезные советы**, **Объявления**. Языки: русский, таджикский, узбекский (латиница), киргизский, казахский.

Приложение — клиент того же сервера, что и веб-версия (`../server`, PostgreSQL). Тексты интерфейса, каталог документов, города, учреждения и советы приходят с сервера и обновляются без выпуска новой версии приложения.

> **Состояние проверки.** Это приложение написано в среде без Flutter SDK (хосты Google и pub.dev там закрыты), поэтому оно **ни разу не собиралось и не запускалось**. Что проверено, а что нет — в разделе «Что проверено» ниже. Первым делом выполните `flutter pub get && flutter analyze && flutter test` и пришлите/исправьте то, что покажут.

## Что нужно

- Flutter SDK (канал stable, Flutter ≥ 3.22 / Dart ≥ 3.4: в теме используются `WidgetState*`), Android Studio (для Android), Xcode на macOS (для iOS).
- Запущенный сервер из корня репозитория (`docker compose up --build`, порт 3000). Для проверки на телефоне сервер должен быть доступен по адресу, который телефон видит; в продакшене — только по HTTPS.

## Первый запуск

В папке `mobile/`:

```bash
flutter create --platforms=android,ios --org ru.example --project-name migrant_guide .
python3 tool/configure_platforms.py     # разрешения Android/iOS, название, текст запроса геолокации
flutter pub get
dart run flutter_launcher_icons         # иконки Android и iOS из assets/brand (знак «S!»)
flutter analyze
flutter test
```

`flutter create` дописывает папки `android/` и `ios/` и не трогает `lib/`, `test/`, `pubspec.yaml`. Скрипт `configure_platforms.py` добавляет доступ в интернет, грубую геолокацию и текст запроса на iOS; он безопасен при повторном запуске. Идентификатор приложения (`--org`) замените на свой до публикации в магазинах.

Запуск:

```bash
# Android-эмулятор (сервер на компьютере разработчика доступен как 10.0.2.2)
flutter run

# iOS-симулятор
flutter run --dart-define=API_BASE_URL=http://localhost:3000

# настоящий телефон в одной сети с компьютером
flutter run --dart-define=API_BASE_URL=http://192.168.1.50:3000
```

Адрес сервера задаётся только при сборке (`API_BASE_URL`, см. `lib/config.dart`).

## Дизайн, название и логотип

- **Название:** «Salam!», одно на всех языках (`app.name` в `content/i18n`). Название в магазинах: «Salam! — документы для мигрантов» (в строках приложения его нет, оно вводится в карточке магазина).
- **Логотип:** знак «S!» — белая S и жёлтый «!» на сине-фиолетовом градиенте. Исходники и PNG: `assets/brand` (`src/*.svg` — исходники, в приложение не входят; в приложение входят `icon.png` и `mark_color.png`). Контуры букв сняты со шрифта Inter Black (SIL OFL).
- **Дизайн** («яркий дружелюбный», макет `preview/index.html`). У каждого раздела свой цвет и своя форма в шапке: Документы — синий и четверть круга, Где оформить — фиолетовый и круг, Полезные советы — оранжевый и арка, Объявления — розовый и обратная четверть. Цвет раздела определяет шапку, нижнее меню, кнопки, ссылки и флажки.
- **Статусы не зависят от цвета раздела и всегда продублированы значком и словом:** «Проверено» (зелёный щит), «Демо, не проверено» (янтарный треугольник и пунктирная рамка карточки), «Обязательно» (красный «!»).
- **Код:** `lib/ui/theme.dart` (цвета, `SectionTone` как расширение темы, `themeFor(Section)`), `lib/ui/brand.dart` (знак, шапки с формами, кольцо прогресса, пунктирная рамка, `SectionScaffold`), `lib/ui/widgets.dart` (карточка `AppCard`, метки, поля).
- **Шрифт:** Inter и Inter Display ExtraBold лежат в `assets/fonts` вместе с лицензией (около 4 МБ; при желании урежьте набором символов). Все буквы из строк пяти языков (ғ ӣ қ ӯ ҳ ҷ ү ө ң, oʻ) в шрифте есть — проверено по `assets/i18n`.
- **Тёмной темы нет:** в утверждённом дизайне её нет, поэтому приложение всегда светлое (`themeMode: light`). Для тёмной темы нужны отдельные палитры четырёх разделов.
- **Адаптация:** на экране ниже 680 dp и при открытой клавиатуре шапка сжимается (без города и крупного заголовка), чтобы оставить место списку.

## Сборка для магазинов

```bash
python3 tool/configure_platforms.py --release-https     # убрать разрешение http — сервер должен быть на HTTPS
tool/sync_i18n.sh                                       # обновить встроенные запасные тексты
flutter build appbundle --dart-define=API_BASE_URL=https://ваш-сервер   # Android (Google Play)
flutter build ipa       --dart-define=API_BASE_URL=https://ваш-сервер   # iOS (App Store), нужен Mac
```

Подпись приложений (ключ Android, сертификаты Apple) настраивается по документации Flutter — в репозитории её нет.

## Как устроено

```
lib/
  main.dart, app.dart        запуск; порядок: язык → город (можно отложить) → основной экран
  config.dart                адрес сервера
  api/                       клиент (токен, сохранённые копии справочных ответов), модели, защищённое хранилище токена
  state/                     AppState: язык, тексты, город и район, ответы для списка, отметки, вход; геолокация
  ui/                        экраны: language, city_picker, docs/doc/checklist, where, tips, ads/ad/ad_form, account/mod, data;
                             тема и фирменные виджеты: theme, brand, widgets
  util/                      ссылки (карта, телефон), разбор JSON
assets/i18n/                 запасные копии content/i18n (пока нет связи с сервером)
assets/brand/                знак «S!»: icon.png, mark_color.png (в приложении); иконки Android/iOS и SVG-исходники
assets/fonts/                Inter и Inter Display (SIL OFL), лицензия рядом
test/                        unit- и сценарные тесты (flutter test)
tool/                        configure_platforms.py, sync_i18n.sh, check_api_contract.py
```

Что и где хранится:

| Что | Где | Зачем |
|---|---|---|
| язык, город и регион, район, ответы для списка, отметки | память телефона (`shared_preferences`) | работает без регистрации |
| токен входа | Keychain / зашифрованное хранилище Android | только для объявлений |
| копии справочных ответов и текстов | память телефона | экраны с документами, адресами и советами открываются без интернета, если их уже открывали |
| **координаты** | **нигде не хранятся** | уходят на сервер один раз для подбора города и забываются |

Разделы «Документы», «Где оформить» и «Полезные советы», а также «Мой список» работают без регистрации. Объявления можно смотреть без входа; подать объявление, откликнуться и пожаловаться — после входа. Паспорта, сканы и контакты пользователей приложение не публикует: связь только через форму отклика, сервер отклоняет объявления с телефонами, почтой, паспортными данными и запрещёнными предложениями.

## Как обновлять материалы

Материалы живут на сервере (`../content`, см. корневой README): меняете файлы, импортируете в базу — приложение подхватывает новые данные само. Пересобирать и заново публиковать приложение нужно только при изменении кода или набора языков. Встроенные запасные тексты обновляются `tool/sync_i18n.sh` перед выпуском сборки.

Демонстрационные записи на сервере помечены в приложении штампом «Демо, не проверено». Перед запуском для пользователей на сервере выставляется `INCLUDE_DEMO_CONTENT=false`, и они пропадают.

## Что проверено

Проверено в среде разработки:

- Все файлы `lib/` и `test/` разобраны парсером Dart без синтаксических ошибок; перекрёстные импорты между файлами сверены скриптом.
- **Соответствие серверу.** `tool/check_api_contract.py <адрес сервера> <почта модератора> <пароль>` выполняет те же запросы, что приложение (72 запроса: документы, города, определение города, учреждения для Москвы, Химок и Казани, список, советы, регистрация, объявление, отклик, жалоба, очередь и действия модератора), собирает все поля ответов и проверяет, что каждое поле, которое читает Dart-код, действительно приходит. Прошло на живом сервере; нарочно внесённая опечатка в имя поля скриптом ловится.
- Сервер, на который опирается приложение, проходит свои тесты (27 API-тестов и 23 сценария веб-версии в браузере).

**Не проверено** (нужен Flutter SDK и устройство или эмулятор):

- компиляция и `flutter analyze` — возможны ошибки типов и предупреждения, которые парсер не видит;
- `flutter test`: написаны юнит-тесты (`test/unit_test.dart`) и сценарные тесты на нужные случаи — выбор языка, ручной выбор города, отказ в геолокации, подтверждение найденного города, смена города, выбор района, учреждение из другого города, отсутствие подтверждённых адресов (`test/flow_test.dart`). Они не запускались;
- внешний вид и поведение на экране, работа с реальной геолокацией и запросом разрешения, переходы в карты, телефон и браузер;
- `configure_platforms.py` проверен только на воссозданных шаблонах `AndroidManifest.xml` и `Info.plist`, не на файлах, созданных вашей версией Flutter;
- версии пакетов в `pubspec.yaml` подобраны по памяти; если `flutter pub get` сообщит о конфликте, выполните `flutter pub upgrade --major-versions` и проверьте сборку;
- сборки под Android и iOS, подпись, публикация;
- **внешний вид.** Дизайн утверждён по HTML-макету (`preview/index.html`), а не по запуску во Flutter. Отступы, размеры и тени перенесены по значениям из макета, но на экране не сверялись: возможны расхождения на узких телефонах и при крупном шрифте системы (разметка проверена только чтением кода). Контраст всех цветовых пар из кода пересчитан (текст не ниже 4.5:1, крупный белый на розовом 3.96:1 при пороге 3:1, рамки полей и флажков 3.4:1);
- иконки: `flutter_launcher_icons` не запускался. Адаптивная иконка Android использует однотонный фон `#3A5BFF` вместо градиента;
- `test/flow_test.dart` написан до смены дизайна и опирается на ключи виджетов (`lang-*`, `tab-*`, `city-chip`, `lang-button` и др.); в новом коде они сохранены. Окно теста теперь размером с телефон (360×780 dp), а переход к карточке документа идёт через `ensureVisible`, потому что цветная шапка занимает больше места, чем прежняя строка. После этих правок тесты не запускались.

## Что подтвердить перед запуском

Всё из корневого README (проверка каталога, адресов и переводов носителями, выключение демо-режима), а также для магазинов:

1. **Политика конфиденциальности** — обязательна (геолокация, учётные записи, пользовательские объявления). Текст запроса геолокации на iOS задан в `configure_platforms.py`.
2. **Требования магазинов к пользовательскому содержимому.** Apple и Google требуют механизм жалоб (есть), модерацию (есть) и, как правило, возможность заблокировать автора и согласие с правилами при регистрации. Блокировки авторов и экрана с правилами пока нет.
3. **Удаление аккаунта из приложения** — требуется Apple и Google Play; на сервере такого действия пока нет.
4. Заставка (splash) и карточка в магазине. **Название «Salam!» и знак «S!» юридически не проверялись**: нужен поиск по реестру товарных знаков (ФИПС, классы 9, 42, 45) и по магазинам приложений, прежде чем регистрировать аккаунт разработчика и заказывать оформление.
5. Второй этап (справочник частных компаний, помогающих с документами) не реализован.
